## 1. 背景与目标

### 1.1 背景

漏洞管理平台 2025 期已完成一批功能交付，需按 COSMIC 方法提交**前后评估材料**（附件 5 等）。功能清单已在 Excel 中维护，但 COSMIC 拆分表中的「功能用户、触发事件、子过程描述、数据移动类型、数据组、数据属性」等字段需结合**真实前后端代码**填写，否则易在评估中被标黄（不认可）或标红（重复）。

### 1.2 目标

基于已确认的功能清单与菜单库，通过**菜单 → 前端页面 → 后端接口 → 数据模型**的溯源链路，自动生成符合模板的 **COSMIC 完整附件 5**，并输出配套的代码映射与异常清单，供人工抽检后提交。

### 1.3 不在本次范围

- 软件需求规格说明书、技术建议书、业务需求信息汇总表的编写（但 COSMIC 拆分必须与之一二三级目录严格对应）
- Git 提交、发版录屏、功能核验现场演示（材料生成后由项目接口人组织）
- 对已废弃功能的 COSMIC 拆分

## 5. 处理流程

### 5.1 总体流程

```text
Step 1  读取功能清单 → 过滤已废弃 → 模块列 forward-fill
Step 2  菜单路径匹配功能菜单.csv → 定位 ALIAS/URL/COMPONENT
Step 3  路由反查 Vue 页面 + API 文件
Step 4  API URL 反查后端 *UI.java + DTO
Step 5  按功能过程生成 COSMIC 行（功能用户/触发事件/子过程/E-R-W-X/数据组/属性）
Step 6  应用知识库规则校验与去重
Step 7  生成附件5 Excel + 时序图 + 代码映射清单 + 异常清单
Step 8  人工抽检（建议 ≥10% 功能点 + 全部异常项）
```

### 5.2 菜单匹配规则（优先级从高到低）

1. **全路径精确匹配**：将 CSV 中 ID→PARENT_ID 递归拼接为 `一级/二级/.../末级`，与「新菜单路径（v3.8.3）」完全一致
2. **末级名称 + 父级链匹配**：路径不一致但末级 NAME 相同且父链语义一致（如「运营·深耕」与库中「运营管理」需建别名表）
3. **ALIAS / COMPONENT / URL 反查**：用末级菜单名在 `router.config.js` 的 `meta.title` 或 path 中搜索
4. **兜底列**：使用「菜单/路径(完成必填)」
5. **仍无法匹配** → 写入《异常待处理清单》，不编造源码

### 5.3 菜单别名映射（执行时需维护）

以下前缀/名称在功能清单与菜单库中可能不一致，执行人应建立 `menu_alias_map.csv`：

| 功能清单中的写法 | 可能对应菜单库写法 | 备注 |
|------------------|-------------------|------|
| `运营·深耕/...` | 需在 CSV 中模糊匹配末级 | 约 40+ 条路径 |
| `运营·深耕(2025期)/...` | 同上 | 含版本后缀 |
| `漏洞管理平台/...` | 可能与「漏洞生命周期管理」并存 | 逐条核对 |
| `信息化资产管理/...` | 资产域菜单 | asset-other-manage |

## 7. COSMIC 字段生成规范

### 7.1 功能用户（F 列）

| 场景 | 写法 |
|------|------|
| 标准页面操作 | `发起者：安全运营人员 接收者：漏洞管理平台` |
| 系统定时/内部任务 | `发起者：系统调度模块 接收者：漏洞管理平台` |
| 跨系统接口 | `发起者：漏洞管理平台 接收者：外部扫描系统`（按实际 Feign/接口调整） |
| 多发起者 | **拆成 1 对 1** 多行功能过程，不写在同一功能用户 cell |

### 7.2 触发事件（H 列）

格式：**操作 + 对象** 或 **对象 + 被操作**

| 功能操作（清单） | 触发事件示例 |
|------------------|--------------|
| 查询按钮 | 点击查询按钮 |
| 新增按钮 | 点击新增按钮 |
| 编辑按钮 | 点击编辑按钮 |
| 删除按钮 | 点击删除按钮 |
| 导入按钮 | 选择文件并导入 |
| 导出按钮 | 点击导出按钮 |
| 程序内部自动执行 | 系统触发CPE数据格式校验 |

### 7.3 子过程与数据移动（J/K 列）

**原则**：每个功能处理由若干子过程组成；**一个子过程 = 一个数据移动 = CFP 1**。

#### 查询类功能过程

| 顺序 | 子过程描述 | 类型 | 说明 |
|------|------------|------|------|
| 1 | 输入/选择查询条件 | E | 用户输入 |
| 2 | 读取xxx列表/详情数据 | R | 读持久化存储 |
| 3 | 展示查询结果 | X | 输出到界面 |

#### 新增类功能过程

| 顺序 | 子过程描述 | 类型 |
|------|------------|------|
| 1 | 输入xxx信息 | E |
| 2 | 保存xxx信息 | W |
| 3 | 展示新增结果 | X |

#### 修改类功能过程

| 顺序 | 子过程描述 | 类型 |
|------|------------|------|
| 1 | 输入修改后的xxx信息 | E |
| 2 | 读取原xxx信息（若需回显） | R |
| 3 | 更新xxx信息 | W |
| 4 | 展示修改结果 | X |

#### 删除类功能过程

| 顺序 | 子过程描述 | 类型 |
|------|------------|------|
| 1 | 选择待删除xxx | E |
| 2 | 删除xxx信息 | W |
| 3 | 展示删除结果 | X |

**注意**：

- **删除** 与 **批量删除** 必须是两个独立功能过程，且 UI 上分别有行内删除与批量删除按钮（知识库第 20 条）
- **列表查询** 与 **详情查询** 若针对同一实体，评估时可能判重复；若清单中同时存在，子过程描述须体现**独立钻取/详情页**，否则在异常清单标注供人工取舍
- **末尾「提示成功与否」的 X** 尽量不单独成行（知识库第 19 条）
- **Redis 缓存读写** 不计点，W 只写数据库持久化
- **静态校验、纯配置开源组件** 不计点（Sheet1 第 8、9 条）

### 7.4 数据组与数据属性（L/M 列）

| 规则 | 说明 |
|------|------|
| 数据组 | 业务实体 + 「信息/配置/记录」等，如「CPE文档信息」「扫描任务信息」 |
| 数据属性 | 从 Vue `columns`/`form`、API DTO 字段提取，中文或英文字段名均可，逗号分隔 |
| 同一功能过程多行 | 同一数据组可重复出现，属性按子过程实际需要填写（可填部分属性） |

**示例（CPE 文档查询）**：

| 功能过程 | 子过程 | 类型 | 数据组 | 数据属性（摘自 API/DTO） |
|----------|--------|------|--------|---------------------------|
| CPE文档查询 | 输入CPE文档查询条件 | E | CPE文档查询条件 | 文档名称,CPE标识,版本,厂商 |
| CPE文档查询 | 读取CPE文档列表 | R | CPE文档信息 | 编号,文档名称,CPE标识,版本,厂商,创建时间 |
| CPE文档查询 | 展示CPE文档列表 | X | CPE文档信息 | 编号,文档名称,CPE标识,版本,厂商,创建时间 |

## 8. 质量规则与规避清单（强制）

来源于 `前后评估知识库.xlsx` 与 `COSMIC填写说明.xlsx`，执行时必须逐条自检。

| # | 规则 | 执行动作 |
|---|------|----------|
| R1 | 材料与功能清单一一对应 | 498 条功能过程均有 COSMIC 行或异常说明 |
| R2 | 一二三级目录严格对应 | 不得修改模块名 |
| R3 | 增删改查分开描述 | 不用「配置」「管理」替代具体操作 |
| R4 | 同实体列表+详情不重复计点 | 检测并差异化描述或人工确认 |
| R5 | 跨功能子过程描述高度相似 → 判复用 | 写具体业务对象名，避免模板化 |
| R6 | 缺少数据移动不认可 | 每条功能过程至少 E + R或W + X |
| R7 | 末尾成功提示 X 不认可 | 省略或合并 |
| R8 | 静态判断不作功能点 | 跳过纯前端校验 |
| R9 | 功能必须有可演示页面 | 映射不到 Vue 的列入异常 |
| R10 | 删除/批量删除需独立按钮 | 分别拆分 |
| R11 | 子过程禁止「第一步、第二步」 | 用业务谓宾描述 |
| R12 | 禁止描述过多中间逻辑过程 | 站在用户交互角度 |
| R13 | CFP 列 | **全部填 1** |
| R14 | A 列修订标识 | 首次提交空白 |
| R15 | 完成后删除模板案例/定义/说明行 | 仅保留评估数据 |
