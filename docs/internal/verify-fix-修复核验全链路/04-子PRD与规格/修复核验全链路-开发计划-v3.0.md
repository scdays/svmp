`MainTaskStatEnum`（10~90）/ `SubTaskStatEnum`（0~4）拆分；`TaskStatCompatMapper` 读兼容旧 0~8；去掉「离线导入」状态语义（模式仍由 tskModel 表达）；前端主/子字典分离。**总评：定向验收通过；刷数延后（R9）。**

### 3.18 Wave O（07-22）- 缓存一致性与设备分配基础设施（R11~R16）

**目标**：实现 PRD §5.2.1 的绝对安全缓存策略，preDispatch 生成的 plan 在 30 分钟内可被 dispatch 原子消费，防止预览与下发不一致、跨会话共享、并发重复提交。

**交付**：
- `IDispatchPlanCacheRepository`（接口）+ Redis 实现 + InMemory 实现（双实现，默认关闭可降级）。

- `DispatchPlanCacheValidator`：校验 owner/token/status（PREVIEWED）/dispatchAttemptCount。
- `DispatchDeviceAssignmentValidator`：校验 engHash 在 candidateDevices 内 + engType bit 二次兜底。

**验收结论**：代码已合入；R16 缓存一致性单测（重复提交、token 伪造、过期、并发 dispatch、Redis 异常、checksum 失败）已落地。待补验收报告（R17 全阶段缓存化联调）。

## 4. 已修复缺陷记录（自 PRD §18 迁入）

> **约定**：新发现的实现缺陷修复后须在本章追加（现象/根因/修复/回归），并在 PRD 修订记录登记版本；每条修复须附可运行回归测试（`test-required-strict`）。

### 4.1 门闸态被 setTask 覆盖，导致 Gate→Scan 级联失效（P0）

- **现象**：确认下发后主任务落库 `WAITING(0)` 而非 `WAITING_VERIFY_GATE(6)`；Gate 回收后 Scan 波永不派生。
- **根因**：`loadSubTasks` 先置 `WAITING_VERIFY_GATE`，随后 `setTask` 无条件 `setTskStat(WAITING)` 覆盖；spawn guard 永不成立。
- **修复**：`setTask` 仅当未处于 `WAITING_VERIFY_GATE` 时才默认落 `WAITING`。
- **回归**：`VulScanTaskSubDomainServiceSetTaskTest#setTask_preservesWaitingVerifyGate` / `#setTask_defaultsToWaitingForNonGate`。

### 4.2 门闸/核验子任务资产 ast_num 为 null（P0）

- **现象**：下发报 `Column 'ast_num' cannot be null`（vul_scan_task_sub_asset）。
- **根因**：`filterAssetsByIps`/`syntheticAssetsFromIps` 只 set assetIp 未 set astNum，与常规路径不一致。
- **修复**：按 IP 聚合回填 astNum；纯 IP 目标每行 astNum=1、source=0。
- **回归**：`#filterAssetsByIps_setsAstNumPerIp` / `#syntheticAssetsFromIps_setsAstNumOne`。

### 4.3 门闸/核验子任务落库字段缺失（P0）

- **现象**：`tsk_id`、`prc_ast_num`、`prc_vul_num`、`tsk_progress` 缺失。
- **根因**：`buildSubTasksFromVerifyFixPlan` 与 spawn 路径比常规 `createSubTask` 少设字段。
- **修复**：补齐 `setTskId` / `setTskProgress(1)` / `setPrcAstNum` / `setPrcVulNum`。
- **回归**：`#buildSubTasksFromVerifyFixPlan_gateSubTaskFieldsComplete`。

### 4.4 前端任务状态标签缺失/越界（P1）

- **现象**：子任务状态列显示裸数字；主任务行 badge 缺失。
- **根因**：前端字典仅 0–3 且用状态码当数组下标，code≥5 越界。
- **修复**：字典补全；新增 `tskStatColor(code)` 按 code 查色。
- **规范**：状态码以后端枚举为唯一数据源；禁止状态码做数组下标（已写入 PRD §5.4）。

```yaml
compliance:
  ledger-online-addr-merge-enabled: true
  verify-fix-strategy-enabled: true
  verify-fix:
    default-version-login: 1027      # 1050 默认手段（PRD §3.4）

vul:
  auto-dispose:
    store: redis                     # 自动化处置状态外置
    async-enabled: true
  dispatch-plan-cache:               # Wave O 缓存基础设施（默认关闭，逐步启用）
    enabled: false                   # 缓存开关；关闭时走旧 dispatch 逻辑（fallback）
    ttl-minutes: 30                  # plan 缓存 TTL
    max-dispatch-attempts: 3         # dispatch 最大重试次数
```

Redis key（Wave O/Q，已去 VerifyFix 前缀）：
- `vul:dispatch-plan-cache:plan:{confirmToken}` - plan 缓存，TTL 30 分钟
- `vul:dispatch-plan-cache:dispatched:{confirmToken}` - 幂等标记，TTL 7 天
- `vul:dispatch-plan-cache:lock:dispatch:{confirmToken}` - 分布式锁，TTL 30s

自动化处置 Redis key：`auto-dispose:run:{runId}` / `auto-dispose:active:{tskId}` / `auto-dispose:lock:*`；run TTL 24h，报告文件 72h。
