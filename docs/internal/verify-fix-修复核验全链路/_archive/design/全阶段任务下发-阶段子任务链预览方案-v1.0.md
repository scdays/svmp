## 0. 目标

将下发抽屉内「仅核验有预览」升级为 **按 `tskPhase` 驱动的阶段子任务链预览（PhaseDispatchPreview）**，对齐原型交互：

1. 阶段 0～4 均有下发前预览表（一行 = 一条将下发的物理子任务）  
2. **1026 交叉扫描验证**：必须选择 **两个不同厂家** 扫描器  
3. **跨级联动**：支持按 **资产数量** 切批，预览按「批次 × 编排步骤」展开  
4. 产品预警 / 系统工单 / 跨级联动 **同一套预览组件**，仅约束差异

**不做**：把 AutoDispose 队列塞进下发抽屉；三菜单三套预览页；改 `open-api-service`。

## 2. 信息架构（对齐原型）

```text
┌─ 任务下发抽屉 ─────────────────────────────────────────┐
│ 基本信息（指令/数量/处置方式/业务阶段）                  │
│ ┌─ 跨级切批（仅跨级） ───────────────────────────────┐ │
│ │ 启用开关 + 每批资产数 + 切批结果摘要                 │ │
│ └────────────────────────────────────────────────────┘ │
│ ┌─ 阶段子任务链预览 · {阶段名} ──────────────────────┐ │
│ │ Alert：链顺序 / 双厂家 / 切批摘要                    │ │
│ │ Table：批次? | 顺序 | 编排步骤 | … | 安全资源 | …   │ │
│ └────────────────────────────────────────────────────┘ │
│ ┌─ 安全资源设备 ─────────────────────────────────────┐ │
│ │ 普通：单选；1026：主扫 + 交叉扫（双厂家）           │ │
│ │ 核验确认态：锁定（沿用现网）                         │ │
│ └────────────────────────────────────────────────────┘ │
│                              [取消] [确认下发]           │
└────────────────────────────────────────────────────────┘
```

### 2.1 按阶段显示矩阵

| 阶段 | 编排链 | 设备列 | 闸门 | 原型要点 |
|------|--------|--------|------|----------|
| 0 潜在预警 | 关联分析 ×1 | 隐藏 | 无设备即可确认 | 产品预警只读 |
| 1 排查 | 漏洞扫描（1028→连通性文案） | 需匹配 | 至少 1 台合法设备 | — |
| 2 验证 · **1026** | 主扫 → 交叉扫 | **双厂家** | 两台不同厂家 | 冲突红框禁用确认 |
| 2 验证 · 1040 等 | 扫描 → 二次扫描 | 单设备可 | 设备匹配 | — |
| 3 修复 | 漏洞修复 ×1 | 1050–1052 隐藏 | 可确认 | 提示不绑定扫描设备 |
| 4 核验 | 连通性 → 修复核验 | 计划内锁定 | `confirmToken` + 全匹配 | **零回归** |

| 顺序 / 编排步骤 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 原修复方式 | — | — | — | — | ✓ |
| 处置方式 / 处置类型 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 安全资源 | — | ✓ | ✓（角色 Tag） | 条件 | ✓ |
| 目标规模 / 依赖 / 过程 / 警告 | ✓ | ✓ | ✓ | ✓ | ✓ |

## 3. 关键规则

### 3.1 1026 双厂家（必须落地）

1. 处置方式 = **1026** 时，设备区切换为「主扫 / 交叉扫」双选。  
2. 校验：两台均选中；**厂家不同**（`vendor` / 厂商码）；不可同一 `engHash`。  
3. 预览两行分别绑定主扫、交叉扫设备；角色 Tag：`主扫厂家` / `交叉厂家`。  
4. 不满足 → Alert error +「确认下发」禁用。  
5. 合并语义遵循《双阶段交叉扫描方案》（部侧默认交集）；本期 UI/下发闸门以双厂家为主，不改 transition 内核。

### 3.2 跨级按资产切批（必须落地）

1. **仅**跨级联动菜单展示切批面板。  
2. 字段：`batchEnabled`、`batchSize`（每批资产数，正整数）。  
3. 切批维度：**资产**（IP/资产单元）；漏洞实例随资产归属。  
4. 预览：每批独立展开一套阶段链（例：资产 56、每批 20 → 3 批；1026 → 每批 2 行 = 共 6 行）。  
5. 下发：按批创建主任务或子任务分组（实现以 Domain 拆批结果为准；一批失败不静默吞掉其它批状态）。  
6. 系统工单 / 产品预警：**不出现**切批面板。

### 3.3 与 AutoDispose 边界

| | 下发前 PhaseDispatchPreview | 下发后 AutoDisposeDrawer |
|--|------------------------------|---------------------------|
| API | 扩展 `pre/dispatch` | `/auto-dispose/*` |
| 目的 | 确认将拆出的子任务 | 驱动执行/上传 |
| wave 文案 | 与 `PhaseChainStepCode` / `WAVE_MAP` 对齐 | 同左 |

## 4. 后端契约（扩展 `pre/dispatch`）

在现有 `VulTaskDispatchDTO` / 返回体上扩展（字段名可微调，语义固定）：

| 入参 | 说明 |
|------|------|
| `procMethod` / `tskPhase` | 现有 |
| `engHashes` | 现有；1026 时 **有序**：`[0]=主扫`，`[1]=交叉扫` |
| `primaryEngHash` / `crossEngHash` | 可选显式字段（与 engHashes 二选一，优先显式） |
| `batchEnabled` / `batchSize` | 仅跨级有效 |
| `menuScope` | 可选：`warn` / `sys` / `ganged`（前端传入，便于校验） |

| 出参 | 说明 |
|------|------|
| `phaseChain` | `{ phase, steps:[{code,label,order}] }` 来自 `PhaseSubTaskChainTemplate` |
| `previewRows` | 扁平预览行（含 `batchIndex`、`wave`、`engHash`、`vendor`、`role`、`warnings`、`targetScale`…） |
| `batchSummary` | `{ enabled, batchSize, batchCount, astTotal }` |
| `dualVendor` | `{ required, ok, message, primaryVendor, crossVendor }` |
| `verifyFixPlan` + `confirmToken` | **阶段 4 保持现有结构零回归** |
| `canConfirm` | 后端综合闸门建议（前端仍做即时校验） |

Domain 建议：

- `PhaseDispatchPreviewBuilder`（或扩展现有 Planner）：按阶段 + 1026 + 切批生成 `previewRows`  
- 1026 校验：`DualVendorScannerGuard`  
- 跨级切批：`AssetBatchSplitter`（按资产列表切分）  
- **禁止**把预览编排堆进 App；App 只组参与返回 DTO

## 7. 风险

| 风险 | 缓解 |
|------|------|
| 切批与现有 dispatch 事务边界 | 明确一批一事务或整单事务；失败可追踪 |
| 1026 与历史单设备数据 | 新下发强制双厂家；旧任务不回填 |
| 核验回归 | phase=4 走原 Planner/Token 路径，单测锁住 |
| 大资产 SCAN 切批性能 | batchSize 下限校验；预览行数上限提示 |
