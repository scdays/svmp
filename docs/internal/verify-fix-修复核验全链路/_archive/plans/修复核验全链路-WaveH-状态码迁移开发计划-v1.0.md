# 修复核验全链路 — Wave H 主/子任务状态码迁移开发计划 v1.0

> **状态**：已执行完成（见 Wave H 验收报告 v1.0）；刷数/快照仍延后  

> **日期**：2026-07-16  
> **前置**：Wave G 主链路推导已落地（展示层，不落库）  
> **目标**：主/子任务状态拆分；去掉「离线导入」状态语义；与主链路对齐

---

## 1. 目标

将共用的 `VulScanTaskStatEnum`（0～8）拆为：

- **主任务状态**：对齐 `任务预检 → 待启动 → 执行中 → 结果回收 → 稽核完成 → 任务结束`（+ 失败）
- **子任务状态**：仅执行机语义（待启动 / 执行中 / 已完成 / 失败 / 已跳过）

在线 / 离线一律用「待启动」等通用文案；模式仍由 `tskModel` 表达。

## 2. 验收标准

- [ ] 后端存在独立主/子状态枚举（或等价码表），写路径不再写入旧 5「待离线导入」语义
- [ ] 读路径兼容旧码（映射层），历史数据可展示新文案
- [ ] 前端主任务 / 子任务字典分离；步骤条与 Tag 无「离线导入」字样
- [ ] Wave G `TaskLifecycleResolver` 改为基于新主状态（或双读映射）
- [ ] v2 核验编排（sequential/parallel）不回归；定向单测绿
- [ ] 文档：PRD 码表章节 + 本计划验收报告

## 3. 不改什么

- 不改 `tskModel` 含义（0 在线 / 1 离线）
- 不改 v2 `wave` 子任务类型、`dispatch-mode`
- 本 Wave **不做** lifecycle 快照表（低优，另立项）
- 不改 open-api-service / Partner 契约（若有外部依赖旧码，仅加兼容映射说明）
