## 开发计划（待确认）

**目标**：按产品研讨纠偏后的 v1.2，将修复核验物理子任务改为「扫描器语义（策略类）」模型，并完成完整报告解析、分层判定与完整 9/10 台账闭环。

**验收标准**：

- [ ] 混合 1050+1051+1052+1053 且 `astUnitNum=-1` → 物理子任务 **=4**（非阶段乘积）
- [ ] 预览一行一物理子任务 + `evidenceCapabilities` 说明；confirmToken 下发有效
- [ ] 一份报告支撑该子任务分层判定；1052/1053 实例级键匹配
- [ ] 每条物理 subTask 完整 opCode 9+10，结果字段齐全，onlineAddr 覆盖负责 IP
- [ ] feature flag 关闭走 legacy；`mvn compile` / 前端 lint 通过

**不改什么**：

- `open-api-service`、Partner `verify-fix` 契约、无关子应用
- 不推倒 P0：DDL / OnlineAddrMerger / Validator / confirmToken 骨架 / 台账动作链

| Wave | Agent | 改什么 | 交付物 |
|------|-------|--------|--------|
| **R1** | B-R1 后端 | StrategyResolver / Planner / 落库 → 策略类 × IP 批 | 物理子任务条数单测 TC-01～04 |
| **R1** | F-R1 前端 | 预览表列改为策略类一行；回归 confirmToken | VerifyFixPlanPreview + BaseInfo/AddTaskDrawer |
| **P2** | B-P2 后端 | 完整报告过滤 + Verdict（§4.3）+ recycle/submit + 完整 10 | TC-05～09 |
| **P2** | F-P2 前端 | ProMethodDrawer 默认 3/10；submit 接线 | 离线处置闭环入口 |
| **Review** | R1 审查 | 对照 PRD §9 / §16.4 | 通过/阻塞清单 |

**预计并行**：Wave R1 内 B-R1 先合入契约后 F-R1 可紧跟（或 API DTO 定稿后并行）；Wave P2 中 B-P2 完成后再开 F-P2；Review 最后。

**分支策略**：继续使用现有 `feature/fix-ledger-log-records`（两端一致）；不新开无关分支。

**研发规范**：GitLab 零【强制】、Commit `[TYPE]` 格式、UTF-8 无 BOM（`esmp-rd-standards`）。未要求不 commit / push。

**严格 Rules**：`java-hard-ban`、`backend-layer-boundary-strict`、`backend-ddd-layers`、`backend-naming`、`test-required-strict`、`security-hard-ban`；前端走 `esmp-frontend-dev` 与既有请求封装。

**专项 Skills**：`esmp-backend-dev`、`esmp-frontend-dev`、`esmp-rd-standards`、收尾 `esmp-code-review-strict`。

**风险/依赖**：

- 现网 v1.1 阶段乘行代码必须改掉，保留 confirmToken / Merger（见 PRD §16）
