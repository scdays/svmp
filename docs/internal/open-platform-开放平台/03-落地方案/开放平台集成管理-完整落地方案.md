## 一、背景与边界

### 1.1 要交付什么

| 交付物 | 说明 |
|--------|------|
| **对外 API** | `/api/open/v1/*` + `/oauth/token`，Partner 机机集成 |
| **网关** | partner-gateway：鉴权、能力码、限流、注入 `X-Partner-Id` |
| **统一管理服务** | open-api-service：Partner 身份、Token、业务编排、治理审计 |
| **集成管理后台** | 运营界面：登记 Partner、生成凭证、配置能力、（P1+）监控 |

规范 §2.1 明确：**Partner 由运营在管理后台登记**，第三方不能自注册。集成管理后台是整条链路的**运营入口**。

### 1.2 工程边界

| 工程 | 维护方 | 本方案中的角色 |
|------|--------|----------------|

## 二、总体架构

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                        asset-manage-master (:13001)                      │
│  登录 JWT ← clover  │  顶栏菜单 ← GET /clover/v3/pub/menu  │  qiankun    │
└───────────────────────────────┬─────────────────────────────────────────┘
                                │ activeRule: /openPlatform
                                ▼
┌─────────────────────────────────────────────────────────────────────────┐
│              asset-openplatform-manage (:13021) 【新建】                   │
│  PartnerList / PartnerForm / PartnerDetail / CredentialModal            │
│  openApiRequest → X-Internal-Admin-Key                                    │
└───────────────────────────────┬─────────────────────────────────────────┘
                                │ 内网 HTTP（不经 gateway）
                                ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                    open-api-service (:35780)                             │
│  /internal/admin/partners/*  管理面                                      │
│  /oauth/token、/api/open/v1/*  开放面                                     │
│  api_invocation、requestId   治理面                                      │
└───────────────────────────────┬─────────────────────────────────────────┘
                                │ Feign / 引擎适配
                                ▼
                         vul-pass 等内部服务

公网 Partner 流量：
  Partner → partner-gateway (:35770) → open-api-service
  （/internal/** 在网关层 40101 拦截，管理 API 仅内网）
```

### 2.1 两类请求，两套鉴权

| 请求类型 | 路径示例 | 鉴权 | axios 实例 |
|----------|----------|------|------------|
| 门户 | `/clover/v3/*` | `Authorization: JWT`（主应用同步） | 可选复用主应用 token |
| Partner 管理 | `/internal/admin/partners` | `X-Internal-Admin-Key` | **`openApiRequest.js`（独立）** |

子应用 mount 时仍从主应用同步 JWT（与 `asset-newleak-manage` 相同），但 **Partner 管理 API 不使用 JWT**，只用 Admin Key。

### 3.5 main.js · qiankun 契约（必须）

```javascript
import './public-path'
import VueRouter from 'vue-router'
Vue.use(VueRouter)

function render (props = {}) {
  const { container } = props
  const mountTarget = container
    ? container.querySelector('#child_openPlatform_container')
    : document.querySelector('#child_openPlatform_container')

  router = new VueRouter({
    base: window.__POWERED_BY_QIANKUN__ ? '/openPlatform' : '/',
    mode: 'history',
    routes
  })
  instance = new Vue({ router, store, render: h => h(App) }).$mount(mountTarget || '#child_openPlatform_container')
}

export async function mount (props) {
  render(Object.assign({}, props.data || {}, { container: props && props.container }))
}
```

| 项 | 要求 |
|----|------|
| `public-path.js` | `main.js` 最早 import 之一 |
| `Vue.use(VueRouter)` | 必须，否则 `<router-view>` 不会被接管 |
| `mount` | 必须保留 `props.container`，并在 `container` 内 querySelector 挂载点 |
| `router.base` | qiankun 下为 `/openPlatform`，与主应用 `activeRule` 一致 |
| `App.vue` | 不要使用 `:key="$route.fullPath"`（qiankun 初始阶段 `$route` 可能未就绪） |
| 独立运行 | `if (!window.__POWERED_BY_QIANKUN__) render()` |

业务结构（STable、列表页）可参考 `asset-newleak-manage`，**mount/container 以本节为准**。

### 3.6 openApiRequest.js 行为

1. `baseURL` = `VUE_APP_OPEN_API_BASE_URL`；若为相对路径（如 `/open-api`）且 `window.__POWERED_BY_QIANKUN__`，则拼接 `window.__INJECTED_PUBLIC_PATH_BY_QIANKUN__`，避免请求落到主应用 `:13001` origin
2. 请求头：`X-Internal-Admin-Key: process.env.VUE_APP_OPEN_API_ADMIN_KEY`
3. 启动检测：Key 为空 → 全局 `adminKeyMissing = true`，页面顶栏 `a-alert type="error"`
4. 响应：`{ code, message, data, requestId }`，`code !== 0` → `notification.error(message)`
5. HTTP 401/403 → 「Admin Key 无效或未配置，请联系运维」

**网关约束**：`/internal/admin/**` 为平台管理面，经平台网关或内网直达 open-api-service；**不要**把管理 API 代理到 `partner-gateway`（partner-gateway 仅承接 `/oauth/token`、`/api/open/v1/*` 等接入方流量）。

## 四、主应用集成（asset-manage-master）

### 4.1 qiankun 注册

在 `src/main.js` 的 `registerMicroApps` 追加：

```javascript
{
  name: 'openPlatform',
  entry: MICRO_APP_OPENPLATFORM || isUseConfJsForString('VUE_APP_API_OPENPLATFORM_URL'),
  container: '#subapp-viewport2',
  activeRule: '/openPlatform',
  props: { data: { store, router } }
}
```

### 4.2 运行时配置

`public/conf/index.js` 追加（**开发期必须为子应用独立端口，禁止指向 master 自身**）：

```javascript
VUE_APP_API_OPENPLATFORM_URL: protocolStr + '//172.16.2.4:13021/',
```

| 环境 | entry 形态 | 说明 |
|------|------------|------|
| 本地 dev | `http://<host>:13021/` | 子应用 devServer 绝对 URL |
| 同域生产 | `/openPlatform` | Nginx 反代子应用静态资源；见 `index-online.js`、`runtime-config.json` |

**错误示例**：`VUE_APP_API_OPENPLATFORM_URL` 写成 `http://<master>:13001/openPlatform/` → qiankun 会递归加载主应用，出现白屏或无限刷新。

Docker/生产：`entrypoint.sh` 或 body attribute `openPlatform` 注入内网 entry URL。

### 4.3 开发期 fallback 路由（菜单未下发时）

后端菜单（`GET /clover/v3/pub/menu`）未包含 `/openPlatform` 时，主应用 vue-router 会 404，子应用无法激活。开发期在 `asset-manage-master/src/router/micro-app-fallback-routes.js` 增加占位：

- `component: 'RouteView'`（仅让主应用路由命中）
- `path` 以 `/openPlatform` 开头（如 `/openPlatform/partner`）
- 由 `generator-routers.js` 调用 `mergeMicroAppFallbackMenus()` 合并

生产环境仍应通过菜单库下发正式路由；fallback 仅作本地/过渡期兜底。

### 4.4 主应用 devServer 代理（可选）

`asset-manage-master/vue.config.js` 可将 `/openPlatform` 代理到 `http://127.0.0.1:13021`，便于同域调试静态资源；**entry 仍应配置为子应用地址**，不能仅靠 proxy 替代 `VUE_APP_API_OPENPLATFORM_URL`。

### 4.5 菜单（顶栏入口）

菜单数据来自 **`GET /clover/v3/pub/menu`**（clover 后端菜单库），**不是** clover-front 代码。

需在菜单库新增（协调公共研发或自有菜单管理权限）：

```text
开放平台（一级或挂在「系统管理」下）
└── 合作方管理    path: /openPlatform/partner
    └── （可选）调用记录  path: /openPlatform/invocation   [P1]
```

**子应用内部侧边栏**由 `router.config.js` 的 `asyncRouterMap` 静态维护（同 `asset-newleak-manage`），不依赖 clover-front。

开发期可直接访问：`http://localhost:13001/openPlatform/partner`（需 master + 子应用 `:13021` 均已启动，且 §4.3 fallback 或菜单已配置）。

### 4.6 微前端自检

接入完成后在 `project_frontend/asset` 下执行：

```bash
node scripts/check-micro-app.js \
  --app asset-openplatform-manage \
  --route /openPlatform \
  --name openPlatform \
  --container child_openPlatform_container \

```

`Failures: 0` 为通过；详见 [微应用脚手架](../../../../../project_frontend/asset/docs/micro-app-scaffold.md)。

### 4.7 常见故障（本次联调沉淀）

| 现象 | 根因 | 处理 |
|------|------|------|
| 访问 `/openPlatform/partner` 提示页面不存在 | 主应用无该路由（菜单未下发且无 fallback） | §4.3 fallback 或菜单库补 `/openPlatform/partner` |
| 白屏 / 无限刷新 | entry 指向 master（如 `:13001/openPlatform/`） | §4.2 改为子应用 `:13021/` |
| 子应用 mount 后 DOM 为空 | `mount` 未传 `props.container` | §3.5 使用 `container.querySelector` |
| 页面只有空白、无表格 | 未 `Vue.use(VueRouter)` | §3.5 |
| 控制台 `$route.fullPath` 报错 | `App.vue` 使用 `:key="$route.fullPath"` | 移除该 key |
| 列表 API `Network Error` | qiankun 下相对 baseURL 打到 master origin | §3.6 拼接 `__INJECTED_PUBLIC_PATH_BY_QIANKUN__` |
| 预检 OPTIONS 失败 | devServer 缺 Allow-Methods/Headers | §3.3 补全 CORS headers |
| Admin API 误走 partner-gateway | 代理目标配置错误 | 管理 API 走平台网关/内网 open-api-service |
