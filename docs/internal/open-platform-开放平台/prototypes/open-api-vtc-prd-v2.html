SOC_DUAL 业务规则
SOC 强制彩扯：每个 SOC Partner 的 scanPolicy 必须为 SOC_DUAL，创建任务时如未传或传其他值，平台强制覆写为 SOC_DUAL。
规则编号规则实现位置
BR-01SOC Partner 必须绑定 SOC_DUAL，强制不可改为 SINGLEOpenTaskOrchestrator.validate()
BR-02单次任务目标 IP 上限 1000 个，超出 422open-api 请求校验
BR-03Nessus 和绿盟 应使用相同扫描目标，联类扫描模板OpenTaskOrchestrator.createSubTasks()
BR-04双 survey 均完成：周期和状态均满足，才触发 MergeServicevul-pass Kafka Listener
BR-05其中一个 survey FAILED：父任务置 PARTIAL_FAILED，只并集成功的一方MergeService.merge()
BR-06dedupKey 冲突时：保留两方中严重等级更高者，其余字段取并集MergeService.dedup()
BR-07Webhook 回调时机： MergeService 写入 rela_oper 完成 后才 notifyvul-pass notify Feign
BR-08每个 Partner 数据沐沐层隔离，不同 Partner 可不能共享实例或任务open-api Domain 层

并集算法详说
dedupKey 公式： sha256(assetIp + ":" + port + ":" + protocol + ":" + service + ":" + vulId)
步骤操作实现类
1收到双方结果列表 (Nessus vulns[] + LM vulns[])MergeService.merge()
2对每个漏洞计算 dedupKeyVulnDeduplicator.computeKey()
3按 dedupKey 建立 HashMapVulnDeduplicator.buildMap()
4遇到冲突：比较两方 severity，保留严重等级更高者MergeConflictResolver.resolve()
5非冲突字段：取并集（如 fixLnk 取两者都有就拼接）MergeConflictResolver.mergeFields()
6并集结果写入 vul_archive_inst (data_origin=OPEN)VulArchiveInstRepository.batchUpsert()
7写入 vul_inst_log_rela_oper (biz_line=OPEN, 双轨)RelaOperRepository.batchInsert()
字段冲突规则规则说明
severity / riskLevel保留更高者
cvssScore保留较高者
remedDesc / fixLnk两方均有则拼接，仅一方有则保留
vulInstCpe / vulInstVer取 Nessus 结果优先

Webhook 规格详表
项目内容
地址类型Partner 提供的 HTTPS callbackUrl
重试策略指数退避: 1s / 5s / 30s / 120s / 600s，共 5 次；全部失败进死信队列
签名方式X-ESMP-Signature: sha256={HMAC-SHA256(body, partnerSecret)}
请求方法POST application/json
超时单次请求 10s
幂等性重试时 eventType+taskId 就是幂等键，Partner 应自行去重
eventType触发时机关键 payload 字段
TASK_COMPLETED并集入库完成taskId, mergedCount, vulCount{nessus,lm}, status, finishedAt
TASK_FAILED任务异常终止taskId, errorCode, errorMsg
PARTIAL_FAILED其中一扫描器失败taskId, failedVendor, mergedCount
EXPORT_READYTaskExport 就绪taskId, downloadUrl, format, expiresAt
INSTANCE_UPDATED实例状态变更taskId, vulInfoId, oldStat, newStat
