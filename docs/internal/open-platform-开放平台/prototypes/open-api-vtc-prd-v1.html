适用范围open-api-service · vul-pass · vuln-task-center
功能编号OPEN-VTC-W0 ~ W4
背景与问题
当前痛点：open-api-service 通过伪造 orderId 调用 POST /vul-scan-task/dispatch，导致数据源不清、双扫无法实现、Webhook 伪造。
问题表现影响
假 orderId 泡氓 考核共用考核数据表考核权益受损
SOC 双扫无法实现仅支持单扫业务承诺失信
数据来源不清OPEN/METRIC/ASSESS 混用上报合规失败
真实 Webhook 缺失回调 MockPartner 信任降低
三大发起方

OPEN SOC Partner

REST API 创建双扫任务，必须 SOC_DUAL：Nessus + 绿盟 并集后 Webhook。

METRIC 指标任务

vuln-model 常态化任务迁移 vul-pass，biz_line=METRIC。

ASSESS 部侧考核

工单驱动，写上报轨 rela_report。

目标架构（Wave 1+）
Partner (SOC) | POST /api/open/v1/tasks/vul v open-api-service | POST /internal/open/v1/tasks (Feign) v vul-pass OpenTaskOrchestrator +- biz_line=OPEN, scan_policy=SOC_DUAL | +- vul_scan_task_sub x2 (Nessus + 绿盟) v Kafka vuln-task-center +- Nessus RSAS +- 绿盟 LM RSAS v 双 survey 完成 -> Kafka vul-pass MergeService +- dedup 并集 -> vul_archive_inst (data_origin=OPEN) +- 运营轨 vul_inst_log_rela_oper v Feign notify open-api WebhookDispatcher +- TASK_COMPLETED -> Partner callbackUrl
关键切断：open-api 不再调 POST /vul-scan-task/dispatch，新内部接口 POST /internal/open/v1/tasks 实现任务源隔离。
双轨存储模型
vul_archive_inst (全平台共用主档) data_origin: OPEN | METRIC | ASSESS | PROD | IMPORT vul_inst_log_rela_oper (运营轨 - 真实轨迹) 写入方: OPEN / METRIC / PROD vul_inst_log_rela_report (上报轨 - 部侧合规) 写入方: ASSESS log_id_lst 完整展现
