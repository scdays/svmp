# platform-admin 多智能体分配执行方案

> 版本：v1.0  日期：2026-06-25
> 上游：`00-主计划.md` + `M1~M5-需求设计.md`
> 性质：定义 M1-M8 各里程碑的多智能体编排方案，作为自动化执行的执行手册。

---

## 0. 执行总原则

### 0.1 编排模式（统一）
每个里程碑用一个 Workflow 编排，结构：

```
Phase 1: 实现阶段（N 个 agent 并行，文件零重叠）
   ├── 共享文件由主流程先行同步编辑（pom/配置/spring.factories/共享接口）
   └── 各 agent 只动独占文件
        ↓ barrier
Phase 2: 收尾验证（1 个 agent）
   ├── 注册共享配置（spring.factories 等，串行）
   ├── starter mvn test（若涉及 starter）
   ├── starter mvn install
   └── platform-admin mvn test（全量，堵跨域盲区）
```

### 0.2 三条铁律（吸收前几轮教训）
1. **共享文件不并行写**：pom.xml、application.yml、spring.factories、EventBusProperties、共享接口等由主流程在 fan-out 前同步编辑，或由收尾 agent 单独改。杜绝并行写冲突。
2. **规则内嵌**：每个 agent prompt 内嵌 DDD 规则块（workflow 子 agent 不自动加载 cursor rules）。
3. **末尾全量验证**：收尾 agent 跑双侧 mvn test，主流程独立复核数字，不轻信 agent 自述。

### 0.3 DDD 规则块（每个 agent prompt 必含）
```
标准调用链：Ui → AppServiceImpl → DomainServiceImpl → RepositoryImpl → Mapper/PO
UI extends BaseUI；App extends AppServiceImpl<DS,D,DTO>；
Domain extends DomainServiceImpl<Repo,D>；Infra extends DatabaseRepositoryImpl<Mapper,D,PO>；
Repository 接口 extends IDatabaseRepository<D>；DO 加 @Component @Scope("prototype")；
Convertor @Component 注册 ConvertHelper；UI 注入 AppService 返回 DTO 不返回 DO；
通用 CRUD 继承基类不手写，仅领域特有方法自实现。
```

### 0.4 验证门禁
每个里程碑收尾必须 platform-admin `mvn test` 全绿（且不破坏 starter 测试），否则主流程介入修复，不进入下一里程碑。

## 9. 执行顺序与自动化策略

```
主流程自主推进顺序：
  M1 → M2 → M3 → M4 → M5   （业务迁移主线，逐个 Workflow + 验证 + 修复）
  ── 业务主线完成后 ──
  M6 → M7 → M8              （治理/扩展，视情况）

每个里程碑：
  1. 主流程先行编辑共享文件
  2. 启动 Workflow（fan-out agent + 收尾验证 agent）
  3. 收到完成通知 → 主流程独立复核 mvn test 数字
  4. 若有遗留编译/测试错误 → 主流程直接修复
  5. 全绿 → 更新 00-主计划.md 进度表 → 推进下一里程碑
```

主流程不再每步停下等用户确认，除非遇到：架构决策分歧、范围超出主计划、或需要外部依赖（如真实 Kafka/DB 联调）。

## 10. 验证脚本（统一）

```bash
# starter（若涉及）
cd <starter> && mvn -o test -Dmaven.test.skip=false -DskipTests=false
cd <starter> && mvn -o install -DskipTests=false

# platform-admin（每里程碑必跑）
cd platform-admin && mvn -o test -Dmaven.test.skip=false -DskipTests=false
```

通过标准：`Tests run: N, Failures: 0, Errors: 0` + `BUILD SUCCESS`。
