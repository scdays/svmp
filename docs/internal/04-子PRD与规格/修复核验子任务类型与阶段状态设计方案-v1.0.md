# 修复核验子任务类型与阶段状态设计方案 v1.0

> **范围**：修复核验阶段（`tskPhase=4`）先行落地；其他工单阶段预留扩展。  
> **关联 PRD**：`修复核验全链路-vul-pass-PRD.md` v1.4.5

---

## 1. 子任务类型（落库 `vul_scan_task_sub.wave`）

| 类型码 | 中文名 | 说明 | 历史兼容 |
|--------|--------|------|----------|
| `CONNECTIVITY_CHECK` | 连通性检测 | 工单全量排查资产 IP；`verify_src_method=1028` | `GATE` |
| `REPAIR_VERIFY` | 修复核验 | 按系统漏洞修复状态筛 IP；1050/1051 等二次核验 | `SCAN` |

读写均通过 `VerifyFixSubTaskKind` 判断，禁止业务代码直接写死 `GATE`/`SCAN`。

---

## 2. 下发模式（`compliance.verify-fix.dispatch-mode`）

| 模式 | 下发行为 | 回收/报告处理顺序 |
|------|----------|-------------------|
| `sequential`（默认） | 仅下发连通性检测；连通性全终态后派生修复核验 | 先连通性，后修复核验 |
| `parallel` | 同时下发两类子任务（参数互不关联） | **仍**先连通性，后修复核验 |

---

## 3. 主任务状态（核验阶段，码值不变）

| code | 枚举 | 展示名（v2） |
|------|------|--------------|
| 6 | `WAITING_VERIFY_GATE` | 待连通性检测完成 |
| 7 | `WAITING_VERIFY_SCAN` | 待修复核验完成 |
| 8 | `WAITING_VERIFY_DONE` | 核验完成 |

---

## 4. 全阶段扩展（规划，本版未实现）

| 业务阶段 | 子任务类型链（规划） |
|----------|----------------------|
| 排查 | 漏洞扫描 |
| 验证 | 漏洞扫描 →（1026 交叉扫描）→ 二次扫描 |
| 修复 | 漏洞修复 |
| 修复核验 | 连通性检测 → 修复核验 |
| 潜在预警 | 关联分析 |

统一链路：**预览 → 下发 → [子任务链] → 回收 → 稽核 → 结束**。

---

## 5. 前端展示约定

- 预览表：**无波次列**；展示「子任务类型」列（`subTaskTypeName` 或 `subTaskKind`）。
- 子任务卡片：Tag 用子任务类型色；避免「门闸」「扫描波」文案。
- 下发模式：预览顶部 Alert 说明 sequential / parallel 及回收顺序。
