## 1. 目标

把工作台步骤条从「仅 1060/1061 核验子状态 4～8」升级为**全工单主生命周期**，中间 `[子任务链]` 按 `tskPhase` 配置化展示与编排；**本 Wave 优先打通修复核验 + 验证两阶段**，其余阶段先落模板与 UI，业务编排可后续增量。

## 2. 验收标准

- [ ] 主链路步骤条对所有相关工单阶段可见（不限 1060/1061），文案对齐：任务预检 → 任务下发 → [阶段子任务链] → 结果回收 → 稽核完成 → 任务结束

- [ ] 验证阶段中间链展示为：漏洞扫描 → 二次扫描（1026 交叉扫描占位可配置）
- [ ] 排查 / 修复 / 潜在预警：至少有**模板 + UI 步骤**；若本 Wave 不改编排，步骤条仍能正确高亮到「下发/回收/稽核/结束」

- [ ] 前端 lint 通过；未要求则不 commit

## 4. 设计要点（G-0 定稿后按此实现）

### 4.1 两层模型

| 层 | 含义 | 展示 |
|----|------|------|
| **主链路** | 预览 → 下发 → 子任务执行中 → 回收 → 稽核 → 结束 | 步骤条外层 / 始终存在 |
| **阶段子任务链** | 由 `tskPhase` 决定中间展开步骤 | 主链路「子任务执行」展开为 1～N 步 |

推荐主链路码（**新增字段或映射视图，避免硬拆现有 0～8 语义**）：

| lifecycleStep | 中文 | 与现有字段关系（草案） |
|---------------|------|------------------------|
| ASSIGN_PRECHECK | 任务预检 | `tskStat=PREVIEW(4)` 或预检态 |
| DISPATCHED | 任务下发 | 已 dispatch，子任务已落库；`WAITING(0)` / `WAITING_IMPORT(5)` / 6 / 7 等 |
| SUBTASK_CHAIN | 子任务链进行中 | 由阶段模板展开；核验阶段映射 6/7 |
| RECYCLE | 结果回收 | 子任务终态齐但未稽核；或 recycle 进行中 |
| AUDIT_DONE | 稽核完成 | `orderAct` 打开/稽核接口成功（产品确认口径） |
| FINISHED | 任务结束 | `tskStat=FINISH(1)` |

> G-0 必须拍板：主链路是**纯前端推导**还是后端返回 `lifecycleStep`；建议 **后端提供推导接口/DTO 字段**，前端只渲染，避免两端规则分叉。

### 4.2 阶段 → 子任务链模板

| tskPhase | OrderPhaseEnum | 子任务链（展示） | 本 Wave 编排 |
|----------|----------------|------------------|--------------|
| 1 | 排查 | 漏洞扫描 | 模板 + UI |
| 2 | 验证 | 漏洞扫描 → 二次扫描 | 模板 + UI；交叉扫描(1026) 可配置占位 |
| 3 | 修复 | 漏洞修复 | 模板 + UI |
| 4 | 核验 | 连通性检测 → 修复核验 | **已有 v2，挂接主链路** |
| 0 | 潜在预警 | 关联分析 | 模板 + UI |

### 4.3 与现有核验 4～8 的关系

| 旧展示（v2） | 新主链路映射 |
|--------------|--------------|
| 预览态(4) | 任务预检 |
| 待离线导入(5) | 任务下发（离线模式）或子任务链准备中 |
| 待连通性检测完成(6) | 子任务链 · 连通性检测 |
| 待修复核验完成(7) | 子任务链 · 修复核验 |
| 核验完成(8) | 结果回收完成 / 待稽核（需 G-0 确认 8 与稽核边界） |
| FINISH(1) | 任务结束 |

**关键决策（同意执行前请确认或回复时注明）**：

1. `WAITING_VERIFY_DONE(8)` 算「结果回收」还是「待稽核」？建议：**8 = 回收完成待稽核**，稽核成功后再到结束。
2. 在线任务无「待离线导入」时，主链路是否跳过该语义？建议：**下发一步合并**，不单独展示「离线导入」。
3. 本 Wave 是否只做「修复核验 + 验证」真实高亮，其它阶段灰色模板？建议：**所有阶段都能走主链路高亮；中间子任务链仅核验/验证有细粒度**。
