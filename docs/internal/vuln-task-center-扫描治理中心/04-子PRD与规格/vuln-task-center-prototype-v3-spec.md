# 扫描治理中心 · 原型 v3 交付规格

> **背景**：v2 原型页面多但交互浅、菜单按技术模块拆分，无法支撑 PRD 3.1 验收与研发对齐。  
> **目标**：达到 `open-platform-admin-prototype.html` 同级信息密度，且 **以 survey 实例工作台为主轴**，覆盖 PRD v0.3 全量能力。

---

## 1. v2 问题诊断

| 问题 | 表现 | v3 对策 |
|------|------|---------|
| 功能零散 | 22 个平级 view，无主线 | 4 域菜单 + **实例工作台** 聚合 |
| 未全覆盖 | 缺报告全流程、计划向导、审计时间线 | 按 3.0 生命周期补全 |
| 交互简陋 | 多数仅一张表 + toast | 每主页面：筛选 + 表 + 抽屉/Modal + 分 Tab |
| 无法交付 | 研发无法按页拆任务 | 每页标注 API、阶段、dev-done/todo、验收点 |

---

## 2. v3 必须实现的页面（Minimum Deliverable）

### 2.1 工作台（1 页）

- 5 张 stat + 待办列表（MISSING / ORPHAN / 报告 failed / offline 节点 / 队列积压）
- 快捷入口：新建扫描、对账、报告中心
- **验收**：点击待办可跳到对应实例/对账行

### 2.2 扫描中心

| 页面 | 必含交互 |
|------|----------|
| 实例列表 | 筛选、进度条、对账/报告状态列、进入工作台 |
| **实例工作台** | **6 Tab**：概览 / 子任务 / 下发详情 / 对账 / 结果摘要 / **报告** |
| 新建扫描向导 | 4 步：场景 → 目标 IP → preview-scanners → 确认下发 |
| 子任务抽屉 | 操控 + 时间线 + 跳转报告 Tab |

**报告 Tab 必含**：

- 子任务 × 报告模板矩阵（行=sub_task，列=模板类型）
- 状态 tag + 生成/重试/下载按钮
- 批量生成 / 批量下载
- Mock：LM generate_report → progress → download

### 2.3 资源中心

- 节点 CRUD 表单（完整字段）
- 节点详情：metrics 图 + 能力勾选 + 扫描模板 + **报告模板** 子 Tab
- 逻辑扫描器 / 场景 / 能力目录（LM+AH 切换）
- 模板与字典：扫描模板 | 报告模板 | 弱口令 三分 Tab

### 2.4 报告中心（新增，3 页）

| 页面 | 必含 |
|------|------|
| 报告任务列表 | 全平台 report_job、筛选、progress、retry、download |
| 模板配置 | 平台模板 code ↔ LM report_type / AH 参数 |
| 导出记录 | 下载历史、文件格式、关联 survey、投递状态 |

### 2.5 治理中心

- 对账列表 + diff 详情 + ORPHAN Modal（保留 v2 并增强）
- 队列三分 Tab（保留）
- 仪表盘 + 告警规则
- 端到端故事 S2/S3/S5 改为 **工作台引导卡片**（非独立菜单）

---

## 3. 交互标准（对标 open-platform v3）

每个 **主列表页** 至少包含：

1. breadcrumb + phase/dev 标注  
2. search-row（≥3 筛选项）  
3. toolbar（新建/批量/导出）  
4. table（≥6 列，含状态 tag）  
5. 行操作 → 抽屉或跳转工作台  
6. pagination mock  

每个 **抽屉** 至少包含：

1. 分 Tab（≥3）  
2. kv-row 或 JSON 参数区  
3. footer 操作按钮（含危险操作 confirm）
