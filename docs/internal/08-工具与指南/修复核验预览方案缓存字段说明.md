# 修复核验预览方案缓存（CachedPlan）字段说明

> 数据源：`svmp/docs/internal/_archive/3.21 Wave R（07-22）- 统一设备匹配 + 缓存数据结构优化.txt`（修复核验流 `tskPhase=4`、`verifyFixFlow=true` 的缓存记录）。
> 本文逐字段说明：**用途** + **写入位置** + **读取/消费位置**，便于排查缓存数据结构与下发物化链路。

## 缓存流程概览

```
preDispatch
  └─ setDispatchPreview -> buildPreviewContext(写 PreviewContext) + VerifyFixDispatchPlanner.plan(写 DispatchPlan)
     └─ saveDispatchPlanToCache -> ConfirmTokenSigner.sign 生成 token + computeChecksum
        └─ RedisDispatchPlanCacheRepository.saveIfAbsent  (JSONUtil.toJsonStr -> Redis)

dispatch（带 confirmToken）
  └─ dispatchWithCachedPlan -> find(反序列化) -> DispatchPlanCacheValidator.validate(token/owner/status/checksum)
     └─ applyDeviceAssignmentsToPlan(按 groupKey 回填 engHash) -> buildTasksFromCachedPlan
        └─ 还原 task（PreviewContext 逐字段回填）+ task.verifyFixPlan=dispatchPlan
           └─ ds.dispatch -> loadSubTasks -> buildSubTasksFromDispatchPlan(按 groups 物化子任务)
```

## 附录 B：核心消费链路速查

- **缓存写入**：`VTDSI.saveDispatchPlanToCache`（:147-180）— 构建 PreviewContext + 取 plan + sign 生成 token + computeChecksum + `RDCR.saveIfAbsent`。
- **缓存校验**：`DPCV.validate` — token 签名、owner、status==PREVIEWED、checksum 一致。
- **缓存还原**：`VTDSI.buildTasksFromCachedPlan`（:269-356）— PreviewContext 逐字段回填 VulScanTaskDO；`verifyFixFlow=true` 时 `task.verifyFixPlan=dispatchPlan`。
