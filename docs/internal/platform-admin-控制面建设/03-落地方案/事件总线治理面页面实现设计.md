## 2. 页面详细设计

### 2.1 EventTraceList（事件轨迹列表）

**路由**：`/event-center/traces`
**API**：`GET /internal/admin/event-center/traces`

#### 搜索栏

| 字段 | 组件 | 说明 |
|------|------|------|
| eventType | `<a-input>` | 事件类型，模糊匹配 |
| topic | `<a-select>` | 可选 topic 列表 |
| sourceService | `<a-input>` | 来源服务 |
| traceId | `<a-input>` | 链路追踪 ID |
| status | `<a-select>` | PUBLISHED / RECEIVED / FAILED |
| 时间范围 | `<a-range-picker>` | 按 occurredAt 过滤 |

#### 表格列

| 列 | 字段 | 宽度 | 说明 |
|----|------|------|------|
| 序号 | - | 60 | 行号 |
| eventId | `eventId` | 200 | 可点击跳转详情 |
| 事件类型 | `eventType` | 180 | `<a-tag>` 展示 |
| topic | `topic` | 160 | |
| 来源服务 | `sourceService` | 120 | |
| 状态 | `status` | 80 | 彩色标签 RECEIVED/FAILED |
| 操作人 | `subjectType`:`subjectId` | 120 | 如 `admin:zhangsan`、`system:SOAR` |
| 租户 | `tenantType`:`tenantId` | 140 | 如 `partner:p-123` |
| 发生时间 | `occurredAt` | 170 | 格式化时间戳 |
| 操作 | - | 100 | 详情 / 时间线 |

#### 行操作
- **详情** → 跳转 `EventDetail`
- **时间线** → 跳转 `EventDetail` 并锚定到 timeline 区域
- **报文** → 弹窗展示事件原始报文（调用 `GET /events/{eventId}/payload`），支持 JSON 格式化、复制、下载

```
├──────────────────────────────────────────────┤
│  ② 消费轨迹卡片（多个，按 consumerGroup 分组）│
│  ┌──────────────────────────────────────┐    │
│  │ consumer: platform-admin-invocation   │    │
│  │ handler: InvocationRecordedEventHandler│   │
│  │ status: SUCCESS  retry: 0             │    │
│  │ startedAt → finishedAt                │    │
│  │ lastError: -                          │    │
│  └──────────────────────────────────────┘    │
│  ┌──────────────────────────────────────┐    │
│  │ consumer: vul-pass-notification       │    │
│  │ handler: VulPassNotificationHandler   │    │
│  │ status: FAILED  retry: 3              │    │
│  │ lastError: connection timeout         │    │
│  └──────────────────────────────────────┘    │
├──────────────────────────────────────────────┤
│  ③ 死信信息（如有）                [查看报文] │
│  failedService / failedHandler / reason      │
│  [重放]  [查看报文] 按钮                      │
├──────────────────────────────────────────────┤
│  ④ 事件时间线（纵向时间轴）                   │
│  ● 14:30:01  published → topic               │
│  ● 14:30:02  consumed by platform-admin → OK │
│  ● 14:30:02  consumed by vul-pass → FAILED   │
│  ● 14:30:02  → dead_letter                   │
└──────────────────────────────────────────────┘
```

#### 数据来源
- `getEventDetail(eventId)` → 发布轨迹 + 消费轨迹列表 + 死信（track 含完整 payload）
- `getEventTimeline(eventId)` → 合并时间线
- `getEventPayload(eventId)` → 获取事件原始报文 JSON（供报文查看弹窗使用）

## 7. 事件身份与审计

### 7.1 身份模型

事件体系需要记录**三层身份**，当前 EventEnvelope 已预留字段但 HTTP 发布路径未填充：

| 层级 | 字段 | EventEnvelope | 当前填充 | 说明 |
|------|------|:---:|:---:|------|
| 租户身份 | `tenantType` / `tenantId` | ✅ 已预留 | ❌ 未填充 | 事件归属哪个租户（partner/internal） |
| 主体身份 | `subjectType` / `subjectId` | ✅ 已预留 | ❌ 未填充 | 事件由谁触发（admin:zhangsan / system:SOAR） |
| 操作人身份 | `operatorId` / `operatorName` | ❌ 无专用字段 | ❌ 无 | 治理操作（重放/发布）由谁执行 |

> 注：`subjectType:subjectId` 承载事件触发者身份，可复用为操作人；治理操作审计需额外记录。

### 7.2 后端改造

#### 7.2.1 EventPublishRequest 新增身份字段

```java
// EventPublishRequest 新增
```

#### 7.2.2 GenericEvent 实现 EventContextAware

```java
public class GenericEvent implements DomainEvent, EventContextAware {
    // ... 现有字段 ...
    private String tenantType;
    private String tenantId;
    private String subjectType;   // → operatorType
    private String subjectId;     // → operatorId

    @Override public String tenantType() { return tenantType; }
    @Override public String tenantId() { return tenantId; }
    @Override public String subjectType() { return subjectType; }
    @Override public String subjectId() { return subjectId; }
```

### 7.5 事件报文存储与查看

#### 7.5.1 问题背景

早期 `event_trace` 表仅存储 `payload_digest`（载荷摘要，VARCHAR(128)），运维人员在治理面看到一条事件轨迹后，无法查看发布者发送的完整报文，只能去翻日志，排查链路断裂。本节补齐完整报文的存储与查看能力。

#### 7.5.2 存储设计

| 表 | 字段 | 类型 | 说明 |
|----|------|------|------|
| `event_trace` | `payload` | LONGTEXT | 完整事件载荷 JSON（信封 + payload），由 EventBus 发布端写入 |
| `event_trace` | `payload_digest` | VARCHAR(128) | 载荷摘要（保留，便于去重/比对） |
| `event_dead_letter` | `payload` | TEXT | 原始载荷（死信表已有，直接复用） |
| `event_dead_letter` | `headers` | TEXT | 请求头（死信表已有） |

> 存储策略：报文随发布轨迹一并落库；死信表在消费失败时由 DLQ 处理器写入，保留消费时上下文（含 headers）。

#### 7.5.3 后端改造

```java
// EventTraceDO / EventTracePO / EventTraceDTO 新增字段
private String payload;   // 完整事件载荷 JSON

// IEventCenterAppService 新增方法
String getEventPayload(String eventId);

// EventCenterAppServiceImpl 实现
@Override
public String getEventPayload(String eventId) {
    if (!StringUtils.hasText(eventId)) {
        return null;
    }
    EventTraceDO trace = eventTraceRepository.findByEventId(eventId);
    return trace == null ? null : trace.getPayload();
}
```

```java
// EventCenterUi 新增端点
@GetMapping("/events/{eventId}/payload")
public ApiResponse<Map<String, Object>> getEventPayload(@PathVariable String eventId) {
    String payload = eventCenterAppService.getEventPayload(eventId);
    Map<String, Object> body = new LinkedHashMap<>();
    body.put("eventId", eventId);
    body.put("payload", payload);
    return ApiResponse.ok(body);
}
```

```
│  │ │ {                                        │ │    │
│  │ │   "eventId": "a1b2c3d4...",              │ │    │
```

**交互**：
- **复制** → 将格式化后的 JSON 复制到剪贴板
- **下载** → 下载为 `{eventId}-payload.json` 文件
