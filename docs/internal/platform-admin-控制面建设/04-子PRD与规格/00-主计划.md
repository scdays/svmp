## 0. 总体结论

platform-admin 的建设分为两条主线，交叉推进：

```
主线一：业务能力迁移（M1-M5）  ← 来源 open-api-service，本文档新增为独立里程碑
主线二：EventBus 治理增强（M6-M8）← 来源实施规划 Phase 6-8
```

迁移原则（继承自 08:59 方案，强化）：

1. **代码搬迁 + 路径保持**：Controller 路径、接口签名、DTO 字段保持不变，前端无感。
2. **包名映射**：`com.vtc.openapi` → `com.vtc.platformadmin`。
3. **共享库不迁库**：过渡期与 open-api-service 共享 `open_api` 库，表两边读写，物理迁库推迟到收口阶段。
4. **DDD 四层合规**：所有迁移代码必须遵循 spore-base-ddd 基类（RepositoryImpl extends DatabaseRepositoryImpl 等，详见 `08-工具与指南/ESMP-AI-Rules索引.md`）。
5. **mock 能力保留**：open-api-service 的 mock 风险排查/修复核验/接入测试/处置测试不动。

### 4.5.6 M3-debt：WebhookSecret 加密存储（✅ 完成，2026-07-04）

**方案**：Webhook secret 用于 HMAC-SHA256 出站签名，平台是签名方，密钥必须可逆恢复，单向 hash 不可行。采用 AES-GCM 对称加密（复用 `common.crypto.key`），密文存入 `webhookSecretHash` 列，明文 `webhookSecret` 列置空。

**实现**：
- 新增 `infra/crypto/WebhookSecretCipher.java`：AES-GCM 加解密，密文格式 `Base64(IV(12B) || ciphertext+authTag)`
- `PartnerRepositoryImpl.saveWebhookSecret()`：加密明文 → 存入 `webhookSecretHash`，`LambdaUpdateWrapper` 显式清空 `webhookSecret`（`updateById` 跳过 null 字段）
- `PartnerRepositoryImpl.findWebhookConfig()`：若 `webhookSecretHash` 非空则解密并填入 DO 的 `webhookSecret` 字段，domain 层始终拿到明文
- `PartnerRepositoryImpl.hasWebhookSecret()`：检查 `webhookSecretHash` 或 `webhookSecret` 任一非空（兼容历史明文数据）
- `WebhookDomainServiceImpl.deliver()/retryDelivery()`：简化为直接 `config.getWebhookSecret()`，移除 hash 降级逻辑和 TODO
- `WebhookSecretGenerator.java`：移除 M3 TODO
- 新增 `WebhookSecretCipherTest`：5 个单测（加解密往返、不同密文、空值、篡改检测）

**向后兼容**：历史数据 `webhookSecret` 列存明文、`webhookSecretHash` 为空，`findWebhookConfig` 直接返回明文，不影响投递。

**验证**：`WebhookSecretCipherTest` 5/5 通过，`PartnerRepositoryImplTest` 4/4 通过。（`ApiInvocationRepositoryImplTest` 有 1 个预存 Mockito PotentialStubbingProblem，非本次引入。）

## 5. 执行模式：多智能体

每个里程碑 M1-M8 采用多智能体并行执行，统一遵循以下模式（吸收前几轮经验教训）：

### 5.1 拆分原则
- **按业务子域拆 agent**，每个 agent 文件集零重叠。
- **共享文件主流程先行编辑**（pom/配置/spring.factories/共享接口），避免并行写冲突。
- **末尾设全量验证 agent**，跑 starter + platform-admin 双侧 `mvn test`，堵跨域测试盲区。

### 5.2 规则注入
每个 agent prompt 内嵌 DDD 规则块（来自 spore-base-ddd，因 workflow 子 agent 不自动加载 cursor rules）：
```
标准调用链：Ui → AppServiceImpl → DomainServiceImpl → RepositoryImpl → Mapper/PO
继承基类：UI extends BaseUI；App extends AppServiceImpl<DS,D,DTO>；
Domain extends DomainServiceImpl<Repo,D>；Infra extends DatabaseRepositoryImpl<Mapper,D,PO>；
Repository 接口 extends IDatabaseRepository<D>；DO 加 @Component @Scope("prototype")；
Convertor @Component 注册到 ConvertHelper；UI 注入 AppService 返回 DTO 不返回 DO。
```

### 5.3 验证门禁
每个里程碑收尾必须：starter `mvn test`（若涉及）+ platform-admin `mvn test` 全绿，否则不进入下一里程碑。

### 5.4 详细分配
见 `多智能体分配执行方案.md`，每个里程碑给出 agent 划分、文件清单、依赖、验收。
